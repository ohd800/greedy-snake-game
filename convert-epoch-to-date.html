How epoch time works

A Unix timestamp counts the number of seconds elapsed since 1 January 1970 at 00:00:00 UTC, known as the epoch. It is a single number with no time zone attached, which is exactly why it is useful for storing dates — and why converting it back requires you to say which zone you want.

date = epoch_start + timestamp seconds

Worked example. The timestamp 1788171007:

1970-01-01T00:00:00Z + 1788171007s = 2026-08-31 10:10:07 UTC

Seconds or milliseconds?

This is the most common source of wrong dates. Classic Unix time is in seconds (10 digits around now), while JavaScript's Date.now() and many JSON APIs return milliseconds (13 digits). This tool looks at the magnitude and tells you which one it assumed.

Frequently asked questions

Are epoch timestamps in seconds or milliseconds?
Classic Unix time counts seconds since 1 January 1970 UTC. JavaScript and many modern APIs use milliseconds instead. This tool detects which one you meant from the size of the number, and tells you which it assumed.
Which time zone is the result shown in?
Both. The converter shows UTC and your device's local time side by side, each clearly labelled, so there is no ambiguity about which one you are reading.
What is the current Unix timestamp?
Press the "Use current time" button to drop the current epoch value into the box. It updates from your device clock.
Does the year 2038 problem affect this tool?
The 2038 problem affects systems that store Unix time in a 32-bit signed integer, which overflows on 19 January 2038. JavaScript uses 64-bit floating point, so this page handles dates well beyond that.
Is my data uploaded anywhere?
No. The conversion runs entirely in your browser; nothing is sent to a server.
